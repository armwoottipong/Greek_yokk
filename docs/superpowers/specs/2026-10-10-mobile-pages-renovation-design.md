# Mobile pages renovation — Design brief

> **SUPERSEDED — 11 ต.ค. 2026:** เปลี่ยนขอบเขตเป็นทุกหน้า/popup/componentsและให้desktop+iPadเป็นเครื่องหลัก ดู [ข้อเสนอออกแบบใหม่](2026-10-11-system-interface-design.md) เอกสารนี้เป็นประวัติ ไม่ใช่ข้อกำหนดปัจจุบัน

## ที่มาและผลลัพธ์ที่ต้องการ

ผู้ใช้อนุมัติแนวทางจากการตรวจหน้าจอมือถือ 390px: ปรับตามลำดับ **คลัง → POS → เมนู → Add-on** ให้ทำงานหลักได้โดยไม่เลื่อนตารางแนวนอน รักษาเอกลักษณ์มาสคอต และใช้ components ร่วมกันเมื่อพฤติกรรมตรงกัน แผนนี้ครอบคลุมหน้ารายการและ popup ที่จำเป็นต่อ flow ของทั้งสี่หน้า ไม่สร้างระบบธุรกิจใหม่

## ข้อกำหนดร่วม

- ธีมเดิม: พื้น #FBF5EA, พื้นการ์ด #FFFCF6, พื้นรอง #F4EBDD, แบรนด์ #780608, ตัวอักษร #352522, เส้นแบ่ง #E8DCCB; ส่วนมาสคอตคง #5E0205
- ใช้ Prompt สำหรับภาษาไทย และ Plus Jakarta Sans สำหรับตัวเลข ไม่เพิ่มฟอนต์หรือ UI/chart library
- หน้ารายการคลัง เมนู และ Add-on ใช้ mobile layout เมื่อความกว้าง <768px; จอ >=768px คงตารางเดิม
- POS ใช้ catalog + cart sheet เมื่อความกว้าง <1024px; จอ >=1024px ใช้ catalog + cart panel ด้านข้าง
- ตรวจที่ 320, 360, 390, 430, 768, 1024 และ 1280px รวมแนวนอน 844×390px
- ปุ่มหลักและ icon-only action มีพื้นที่กดอย่างน้อย 44×44px; ข้อความเนื้อหาบนมือถืออย่างน้อย 12px และข้อความประกอบอย่างน้อย 11px
- หน้าและการ์ดมือถือไม่เลื่อนแนวนอน; แถบหมวดหมู่ POS และตาราง desktop เลื่อนแนวนอนได้ภายในขอบเขตของตัวเอง
- ใช้ AppSelect, AppCheckbox, ModalShell และระบบยืนยัน/แจ้งเตือนเดิม ไม่สร้างชุด dropdown หรือ checkbox ซ้ำ
- Mobile sheet มี header/footer คงที่และ body เลื่อนเอง รองรับ safe area และคีย์บอร์ด ห้าม body/footer ถูกตัดนอกหน้าจอ
- เปิด overlay แล้ว background ไม่เลื่อนหรือรับโฟกัส; overlay ชั้นบนรับโฟกัส ปิดแล้วกลับ trigger หรือจุดสำรองที่ยังอยู่
- แอนิเมชัน sheet เข้า 200ms ออก 160ms; ไม่มีแอนิเมชันเมื่อ prefers-reduced-motion: reduce
- คง schema, localStorage keys, GAS sync payload, การคำนวณ GP/ต้นทุน/ราคา, วิธีจัดสรรล็อต และการ checkout เดิม
- ไม่ส่งข้อมูลร้านจริงระหว่างตรวจ UI และไม่ล้าง/นำเข้าข้อมูลจริงเพื่อทดสอบ

## 1. คลังวัตถุดิบ

บนมือถือแสดงหัวข้อสั้น “คลังวัตถุดิบ” ตามด้วยตัวเลขสรุป 2×2 ซึ่งคงความหมายเดิม มีคำสั่ง “รับเข้า” และ “ตรวจนับ” ที่เห็นทันที ส่วนปรับยอด ประวัติ และเพิ่มวัตถุดิบอยู่เมนู “เพิ่มเติม” พร้อมชื่อเต็ม

ค้นหาอยู่เต็มแถว ตัวกรอง role/category/รายการจัดเก็บอยู่ sheet แยก ไม่มี date picker เพราะหน้าคลังแสดงยอดปัจจุบัน ปิดโดยยกเลิกไม่เปลี่ยนตัวกรอง กด “ใช้ตัวกรอง” แล้วแสดงจำนวนเงื่อนไขที่ใช้อยู่

แต่ละการ์ดแสดงไอคอน ชื่อ หมวด ยอดคงเหลือพร้อมหน่วย สถานะ และการเปลี่ยนแปลงที่ยังไม่บันทึก ปุ่มหลักเป็น “รับเข้า” หรือ “ผลิต” ตาม flow เดิม รายละเอียดต้นทุน วันรับ วันหมดอายุ และล็อตเปิดแบบขยาย คำสั่งจัดเก็บ/คืนค่า/ลบถาวรใช้ข้อจำกัดและการยืนยันเดิม

ล็อตแสดงสถานะกำลังใช้ ยอดคงเหลือ วันรับ/หมดอายุ และคำสั่งเฉพาะล็อต ห้ามเปลี่ยนล็อตเพียงเพราะเปิดรายละเอียด สต็อกร่างมีแถบสรุป “ยังไม่บันทึก N รายการ” พร้อม “ตรวจรายการ”, “ยกเลิก”, “บันทึก” และช่องว่างด้านล่างเพื่อไม่บังการ์ด

## 2. POS

บนมือถือสินค้าเป็นพื้นที่หลัก เลือกช่องทางขายจาก AppSelect แสดงชื่อช่องทางและ GP ปัจจุบัน ค้นหาเต็มแถว หมวดเป็นแถบเลื่อนเฉพาะตัว การ์ดสินค้า 2 คอลัมน์ ชื่อไม่เกินสองบรรทัด ราคาเด่น คงคำเตือนของหมดแต่ขายต่อได้

ตะกร้าปิดอยู่เริ่มต้น แถบล่างแสดงจำนวนชามและยอด subtotal ที่ลูกค้าต้องชำระ กดเพื่อเปิด cart sheet ไม่มีการ checkout จากแถบล่างโดยตรง ตะกร้าว่างกดเปิดดูได้และแสดงข้อความแนะนำสั้น

CartPanel ใช้ร่วมทั้ง desktop และ sheet: รายการ/add-ons/จำนวน/ลบ/หมายเหตุ/วิธีชำระ/ยอดรวม/GP/ต้นทุน/คำเตือนล็อต/ชำระเงิน ตัวเลขใช้ store เดิม ปิด sheet หรือเปลี่ยนขนาดหน้าจอไม่ล้างตะกร้า หมายเหตุ หรือวิธีชำระ

Checkout และการเปลี่ยนล็อตอาจเปิด confirmation/shortage dialog ทับ cart sheet; ต้องคงลำดับ overlay หลังยกเลิกยังเห็นตะกร้า หลังสำเร็จปิด sheetและแสดงใบเสร็จตามระบบเดิม ปุ่มชำระมีการป้องกันกดซ้ำระหว่างรอผล

## 3. จัดการเมนู

Mobile toolbar: ค้นหาเต็มแถว ปุ่มตัวกรองหมวด/ช่องทางราคา และ “เพิ่มเมนู” รายการเป็นการ์ดหนึ่งคอลัมน์ แสดงชื่อ หมวด ราคาในช่องทางที่เลือก สถานะ Add-on/Package พร้อม “ดูสูตร” และ “แก้ไข”; “ลบ” อยู่รายละเอียดคำสั่ง ไม่ใช้ทั้งการ์ดเป็นปุ่มแก้ไข

ช่องทางราคาของหน้าจัดการเป็น state ของหน้านี้ ค่าเริ่มต้นใช้ช่องทาง POS ปัจจุบันที่ยังมีอยู่ หรือช่องทางแรก ไม่เปลี่ยน store.currentPlatformId; ราคา 0 แสดง ฿0 ราคาที่ไม่กำหนดแสดง “ยังไม่ตั้งราคา” และไม่มีช่องทางแสดงข้อความชัดเจน

ดูสูตรเปิดรายละเอียดอ่านง่ายบนมือถือโดยแยกวัตถุดิบ/ปริมาณ/ต้นทุน/ความพร้อม เมนูที่อ้างวัตถุดิบหายแสดงสถานะ “ไม่พบวัตถุดิบ” คงสูตรคำนวณเดิม ไม่บันทึกอะไรจากการเปิดดู ปุ่ม “แก้ไขสูตร” ปิดรายละเอียดก่อนเปิด MenuEditModal

MenuEditModal จัดกลุ่มข้อมูลเมนู ราคา สูตร และสิทธิ์เป็นส่วนที่อ่านง่ายบนมือถือ ใช้ form state และ validation เดิม ช่องกรอกจำนวนและราคาไม่บีบ และเข้าถึงปุ่มบันทึกได้เมื่อคีย์บอร์ดเปิด

## 4. Add-on / ท็อปปิ้ง

ใช้ mobile toolbar และการเลือกช่องทางราคาแบบเดียวกับหน้าจัดการเมนู การ์ดหนึ่งคอลัมน์แสดงไอคอน ชื่อ หมวด ราคา และวัตถุดิบที่ผูกพร้อมปริมาณต่อครั้ง; ราคาช่องทางอื่นดูในรายละเอียด ไม่เรียงราคา 4 ช่องทางบนทุกการ์ด

ไม่มี materialId แสดง “ไม่ผูกวัตถุดิบ”; materialId มีแต่ค้นไม่พบแสดง “ไม่พบวัตถุดิบที่ผูก” โดยไม่สร้างหรือลบข้อมูลอัตโนมัติ ใช้ปุ่ม “แก้ไข” ชัดเจน และยืนยันก่อนลบตาม flow เดิม

AddonEditModal แบ่ง header/body/footer โดย body เลื่อนเอง ปุ่มบันทึกอยู่ footer ข้อมูลชื่อ หมวด ราคา วัตถุดิบ และ amountUsed ยังใช้กฎเดิม คีย์บอร์ดและชื่อยาวต้องไม่ดันปุ่มออกนอกจอ

## ส่วน Header ที่เกี่ยวข้องกับทั้ง 4 หน้า

Hamburger ไม่มีพื้นหลังอยู่มุมซ้ายบนเหมือนปัจจุบัน ย่อ title/subtitle เฉพาะมือถือ เก็บประวัติกิจกรรมเป็น quick action และรวม “ล้างข้อมูล”, “โหลด Demo”, “สำรองไป Sheets” ไว้ปุ่มเพิ่มเติม; ห้ามลดขั้นตอนยืนยันเดิม และ drawer ต้องไม่เปิดพร้อมเมนูเพิ่มเติม

## ไม่รวมในรอบนี้

ไม่รีโนเวท Dashboard/Settings ซ้ำ ไม่เพิ่มรายงาน/สิทธิ์ผู้ใช้/ระบบชำระเงินจริง ไม่เปลี่ยนนโยบายขายของหมด ไม่เพิ่ม date filter ให้ยอดคลังปัจจุบัน ไม่เพิ่ม pagination/virtual scrolling โดยไม่มีหลักฐานว่าจำเป็น ไม่เปลี่ยนสูตรต้นทุนหรือคำนวณกำไร

## ผ่านงานเมื่อ

ทั้งสี่หน้าใช้งานหลักได้ด้วยนิ้วโดยไม่เลื่อนตารางข้างบนมือถือ ข้อมูลที่มองเห็นตรงกับ desktop/Pinia actions เดิม กลับขนาดหน้าจอได้โดยไม่สูญเสียงานที่ยังไม่บันทึก การบันทึก/checkout เกิดครั้งเดียวต่อการยืนยัน และผ่าน unit/integration, lint, build และ browser QA ตามแผน
