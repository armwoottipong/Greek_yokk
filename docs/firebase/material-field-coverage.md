# ขอบเขตข้อมูลวัตถุดิบในโมเดลทดลอง

ตรวจแอปเดิมและโครงสร้างไฟล์สำรองวันที่ 21 ตุลาคม 2026 เอกสารนี้อธิบายต้นแบบทดสอบ ไม่ใช่ codec นำเข้า/ส่งออกที่เปิดใช้งานแล้ว

| ฟิลด์เดิม | ตัวแทน/คำสั่งที่รองรับ | เงื่อนไข |
| --- | --- | --- |
| `id` | `id` + `legacyId` จากตัวแปลงรหัส | รหัสคงเดิมเชิงความหมาย ห้ามแก้ผ่าน metadata |
| `name`, `emoji`, `minAlert` | `material_metadata`, `minAlertQ` หน่วยย่อย 1/100 | ข้อความไม่เกิน 160/32 ตัว และยอดเตือนไม่เกิน 1,000,000,000 หน่วยย่อย |
| `category` | patch `material_details` | ข้อความเดิมไม่เกิน 160 ตัว หรือ `null`; หมวดเก่าไม่เปลี่ยนชนิดหรือกฎวันหมดอายุ |
| `packUnit` | patch `material_details` | ชื่อหน่วยแพ็กไม่เกิน 32 ตัว หรือ `null`; ไม่เปลี่ยนหน่วยฐาน/ขนาดแพ็ก/ต้นทุน |
| `shelfLifeDays` | patch `material_details` | `null` หรือเลขจำกัด 0–100,000 รวมทศนิยม ไม่ปัดค่า; ไม่เขียนวันหมดอายุล็อตเดิมใหม่ |
| `isSubIngredient` | patch `material_details` | ธง boolean เพื่อรองรับข้อมูลเดิม; บทบาทจริงคำนวณจากสูตรที่อ้างอิง |
| `unit`, `packSize`, `unitCost`, `packCost` | `material_measure`, `packCostCents` | คำสั่งแยกจากรายละเอียด; ไม่แก้ต้นทุนล็อตประวัติ |
| `inventoryType` | `material_type` | ชนิดชัดเจน ไม่อนุมานจากชื่อหรือหมวดระหว่างแก้ข้อมูล |
| `hasSubRecipe`, `yieldQty`, `subRecipe` ที่เปิดใช้ | `productionRecipe`, `production_recipe` | สัดส่วนเป็นหน่วยย่อย 1/100; ขอบเขตวัตถุดิบเข้า 1–2 ตัว พร้อมดัชนีอ้างอิงกลับ |
| นิยามสูตรผลิตที่ปิดไว้ | `legacyInactiveProduction` ใน projection | เก็บเฉพาะฟิลด์เดิมที่มีอยู่จริง ได้แก่ hasSubRecipe/yieldQty/subRecipe ไม่ถือว่าเป็นสูตรผลิตที่เปิดใช้ และไม่อนุญาตแก้ผ่านรายละเอียด |
| `stock`, `lots` | รับเข้า/ผลิต/ตรวจนับ/ขาย/คืนบิล/สลับล็อต | `lotQty` เป็นยอดปัจจุบัน รักษารหัสล็อตและข้อมูลล็อตเดิม |
| `lastStockInDate`, `expiryDate` | `lastStockInDay`, `expiryDay` ผ่านคำสั่งสต็อก | ห้ามแก้ผ่าน shelf-life หรือหมวด |
| `isDeleted` | `deleted`, `material_archive` | ปิด/เปิดคืนตามเงื่อนไข ไม่ลบเอกสารถาวร |
| `categories.material` | `legacyMaterialCategories` ใน source projection | เก็บรายการและฟิลด์เดิม เช่น label/icon/dateTrackingMode; อ่านอย่างเดียวในต้นแบบนี้ |

`material_details` รับเฉพาะ 4 ฟิลด์รายละเอียดข้างต้น ครั้งละหนึ่งฟิลด์หรือหลายฟิลด์ บันทึกค่าก่อนแก้พร้อมตำแหน่งฟิลด์ที่มีอยู่จริง และ patch ในประวัติที่แก้ไม่ได้
การไม่ส่งฟิลด์หมายถึงคงค่าเดิมและคงสถานะไม่มีฟิลด์ ต่างจากส่ง `null`, `0`, `false` หรือข้อความว่าง ไม่ตัดช่องว่าง ไม่แปลง string เป็น number และไม่ใช้ค่า fallback แทนข้อมูลเดิม
แก้ได้เฉพาะวัตถุดิบที่ยังเปิดใช้และมีในทะเบียน การแก้ที่ไม่เปลี่ยนข้อมูลถูกปฏิเสธ ร้าน/วัตถุดิบ/ประวัติบันทึกพร้อมกัน 3 เอกสาร โดยไม่เปลี่ยน catalogue/cache revision

ยังต้องรับรอง codec/import/export ทั้งฐานข้อมูล ประวัติบิล/กิจกรรม นิยามต้นทางที่ยังไม่ได้เปิดใช้ ขอบเขตขนาดเอกสาร และฟิลด์เพิ่มเติมนอกตารางก่อนนำเข้าจริง
ข้อมูลในไฟล์สำรองต้นฉบับยังเป็นแหล่งอ้างอิงครบถ้วน ไม่มีการนำเข้าร้านจริงหรือแก้ไฟล์ต้นฉบับในรอบนี้
