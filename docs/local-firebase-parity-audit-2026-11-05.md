## เส้นทางที่ตรวจร่วม

- ใช้ source เดียวทดสอบ Local และข้อมูลหลัง compileCoreImport: ช่องทางหน้าร้าน/Delivery, ตัวเลือกฟรี/คิดเงิน, ยอดขาย, GP, กำไร, ตัดสต๊อก, คืนบิล, รับเข้า และผลิต
- หน่วย g, ml, ใบ และลูกยังอ้างอิงข้อมูลคลัง; ค่า quantity และเงินแปลง scale 100 เพียงครั้งเดียว
- ตรวจ namespace/ID ของรูป, permission ของ Admin/Manager/Viewer, immutable pending command และการปฏิเสธข้อมูลที่ปลอมความสัมพันธ์
- ตรวจ provider ของหน้าคลัง/เมนู/ตัวเลือก และ model props ของ Dashboard/Settings/ใบเสร็จ: เส้นทาง Firebase ไม่เปลี่ยนไปบันทึก Local
- ตัวสำรอง/นำเข้ายังคง format, generation และการเก็บต้นฉบับใน archive เดิม

## ผลตรวจ

- Regression tests ของจุดที่พบแสดง failure ก่อนแก้ และผ่านหลังแก้
- Firebase Emulator: 64 ผ่าน, 1 ข้ามตามเงื่อนไขเดิม
- lint และ production build ผ่าน
- ชุดทดสอบรวม: 1,592 ผ่าน, 1 ข้ามตามเงื่อนไขเดิม; ผลเผยแพร่ตรวจผ่าน Actions และ version.json ก่อนแจ้งผู้ใช้
- การตรวจทานโค้ดแยกไม่พบปัญหาที่ต้องแก้เพิ่มใน diff นี้

## ขอบเขตของผลตรวจ

บิลเก่าที่ไม่ได้เก็บราคาแยกรายตัวเลือกจะแสดงว่ารวมในยอดสินค้า โดยคงยอดบิลที่บันทึกไว้ ไม่คำนวณราคาเก่าจาก catalog ปัจจุบัน ชื่อเมนูที่ไม่มี snapshot จะระบุว่าเป็นชื่อปัจจุบัน

การแก้ตัวแปลงข้อมูลมีผลต่อไฟล์ที่เตรียมใหม่ ไม่ใช่การย้ายข้อมูลจริงย้อนหลัง การตรวจนี้ใช้โค้ด ชุดทดสอบ และ Emulator จึงไม่ใช่หลักประกันว่าทุกอุปกรณ์หรือเหตุขัดข้องระยะยาวจะไม่มีข้อผิดพลาด
