# รูปเมนูและวัตถุดิบ

ในฟอร์มเพิ่ม/แก้ไขเมนูหรือวัตถุดิบเดิม เลือก **แนบรูป** แล้วลากรูปหรือปรับ
ซูม/ตำแหน่งด้วยตัวเลื่อน กด **ใช้รูปนี้** และบันทึกฟอร์ม รูปแสดงสัดส่วน 1:1
ในพื้นที่รูปเดิมของหน้าขาย เมนู และคลัง ไม่มีการเปลี่ยนโครงสร้างหน้า
เมื่อไม่มีรูปหรือตัวรูปโหลดไม่ได้ ยังแสดงอีโมจิเดิม

- รับ JPG, PNG, WebP ต้นฉบับไม่เกิน 10 MB และ 25 ล้านพิกเซล
- ผลลัพธ์ JPEG 512×512 ไม่เกิน 150 KiB พื้นโปร่งใสเปลี่ยนเป็นสีขาว
- ยกเลิกครอปไม่เปลี่ยนรูปเดิม; ลบรูปยังต้องบันทึกฟอร์ม
- ตำแหน่งและซูมใช้เมาส์ สัมผัส หรือคีย์บอร์ดกับตัวเลื่อนได้
- ถ้าข้อมูลรายการบันทึกสำเร็จแต่รูปไม่สำเร็จ ฟอร์มคงรูปไว้ กดบันทึกซ้ำจะลอง
  ส่งเฉพาะรูป ไม่ส่งข้อมูลสต็อก/สูตรซ้ำ หากแก้ข้อมูลอื่นเพิ่มหลังบันทึกแล้ว
  ระบบขอให้เปิดรายการใหม่ก่อนแก้ข้อมูลนั้น
- รูปถูกแก้พร้อมกันจากอีกเครื่องจะไม่ถูกเขียนทับเงียบ ๆ ให้โหลดรูปปัจจุบันใหม่

## ข้อมูลและสิทธิ์

Firebase เก็บรูปแยกที่
`shops/{shop}/generations/{generation}/catalogImages/{kind}_{entityId}`
โดย `kind` คือ `menus` หรือ `materials` ไม่ฝังรูปใน shop/catalog root,
material document หรือ operation receipt และยกเว้นการทำดัชนีทุกฟิลด์ของรูป
ติดตามรูปด้วย listener เฉพาะรายการที่มี component แสดงอยู่

บัญชี Google ที่อยู่ใน allowlist และมีสิทธิ์ Manager/Admin เท่านั้นที่อ่าน/เขียน
เอกสารรูปได้ ต้องเป็น generation ที่ active และเขียนได้เมื่อยืนยัน server ได้
transaction ตรวจ root, entity และ revision ของรูป ไม่มีคิวอัปโหลดออฟไลน์
การใช้งานยังอยู่บน Spark แต่ใช้โควตา Firestore สำหรับจัดเก็บและอ่านรูป
ไม่ได้เปิด Cloud Storage, Functions หรือ billing

`local.html` เก็บรูปในฐานข้อมูลเครื่องเดิม มีการตรวจรูปเมื่อ import/restore
และรายงานข้อผิดพลาดหากพื้นที่เก็บไม่พอ ไม่ซิงก์กับ Firebase

## สำรองและกู้คืน

Firebase business backup รวม collection `catalogImages` พร้อม integrity checksum
และขีดจำกัดไฟล์สำรอง 20 MiB เดิม รูปมี revision แยกจาก revision ธุรกรรม
จึงเป็น snapshot ที่สอดคล้องรายเอกสาร ไม่ใช่ภาพถ่ายทุกภาพ ณ เวลาเดียวกัน
`scripts/backup-rehearsal.js` รองรับทั้งไฟล์เดิมที่ไม่มีรูปและไฟล์ที่มีรูป
โดยตรวจชนิด/ขนาด/ตัวระบุและคงข้อมูลรูปไว้ในแผนกู้คืน
ยังไม่มีการเปิดการนำเข้าไฟล์สำรองสู่ production อัตโนมัติ

## หลักฐานตรวจรับ

ชุดทดสอบครอบคลุมขอบเขตครอปภาพแนวตั้ง/แนวนอน การจำกัด JPEG,
revision conflict, offline/context fencing, สิทธิ์ใน Rules และการลองส่งเฉพาะรูป
หลัง business save สำเร็จ โดยจำลองยอดสต็อกเปลี่ยนระหว่างนั้น
ตรวจ UI ด้วย Chromium/Edge แบบแยกข้อมูลทดสอบที่ 1280, 820 และ 390px
ทดสอบเลือกไฟล์ ยกเลิก ครอป บันทึก และ reload พบผลลัพธ์ 512×512
โดยไม่มี horizontal overflow ภาพใน POS เป็น 1:1
การตรวจนี้ไม่อัปโหลดรูปหรือเปลี่ยนข้อมูลธุรกิจจริงใน production
